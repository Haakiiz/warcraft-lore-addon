**Merknad om lupa (et problem i dette testmiljøet, ikke i addonen):** Første gang feilet alle Lua-testene med `ModuleNotFoundError: No module named 'lupa'`. Grunnen var at `pip` installerte lupa til en annen Python enn den `python3` bruker. Med `python3 -m pip install lupa` virket alt. GitHub Actions bruker ett og samme Python-oppsett og får derfor neppe dette problemet. Hvis det skulle skje der, er fiksen å bytte `pip install lupa` med `python3 -m pip install lupa` i `release.yml`.

**Liten forbedring (valgfri):** `tests/test_forever_ids.py` finnes, men blir ikke kjørt i `release.yml`. Minste fiks: legg til linjen `python3 tests/test_forever_ids.py` i steget "Lua tests".

**Ett spørsmål om oppførsel (ikke en feil):** En veteran teller bare som «møtt» når du holder musepekeren over den (tooltip, `Core.lua:919`) eller tar den som target (`Core.lua:1223`). Varselet som kommer fra navneskiltet eller kartposisjonen merker den ikke som møtt. En veteran du bare har sett på navneskiltet, vil derfor varsle på nytt hver gang du logger inn, helt til du holder musepekeren over den eller targeter den. Er det slik du vil ha det, eller skal varselet i seg selv telle som et møte? Hvis det skal telle, er minste fiks å kalle `ns.MarkMet(npcID)` i `nameplateAdded` rett før `announce(...)` (`Core.lua:884`). Jeg har ikke endret noe.
